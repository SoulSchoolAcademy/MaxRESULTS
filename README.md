## Source-of-truth rules

- The production Results experience has one canonical complete HTML artifact.
- `window.MAXESS_RESULT` is the authoritative runtime result object.
- Do not create competing renderers, result sources, hero systems, or uncontrolled patch layers.
- Preserve the approved working experience before making structural changes.
- A candidate is not automatically authoritative because it is newer, larger, committed, or tested.
- GitHub state is not proof of Groove publication.
- Do not declare live verification without checking the public target.

## Development protocol

**READ → MAP → BASELINE → SOURCE-LOCK → PLAN → MODIFY → REASSEMBLE → BUILD → REFETCH → DIFF → TEST → OSCAR → FIX → RETEST → LIVE-CHECK → PARITY VERIFY → DELIVER**

## Clean-repo principle

This repository is intentionally not a copy of every historical MAXESS experiment. Durable laws, product requirements, deployment rules, validated assets, and important lessons are consolidated into clear documents. Historical implementation artifacts remain in the original repository as reference material until a canonical production source is migrated and verified.

## Product requirements

The Results experience must work simultaneously as:

1. an interactive web experience;
2. a guided Naya experience;
3. a personalized written report; and
4. an intentionally designed printable/downloadable PDF.
