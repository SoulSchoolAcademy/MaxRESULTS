## 1. Decision

Naya Power Player must be architected as a complete product before modular fabrication begins.

The team must know the destination, complete page journey, block responsibilities, visual language, intelligence model, identity model, network direction, platform constraints, engineering seams, QA model, and future architecture before constructing E01.

The nine blocks are **construction units**, not the architecture itself.

## 2. New product hierarchy

The system is now understood as:

**NayaNET → Free Identity + Intelligent Hub → Naya Power → Superbrain → Collective Intelligence**

NayaNET is the broader intelligent network.

The Intelligent Hub is the user's free command station/toolbox and identity home.

Naya Power is the premium intelligence experience.

The Superbrain is the user's sovereign/private intelligence environment.

Collective Intelligence is the opt-in, privacy-gated layer through which generalized wisdom can compound across independent intelligence systems.

## 3. Free account direction

Every visitor should be able to enter the ecosystem with minimal friction.

Initial account creation should require only the person's name, subject to the final production authentication architecture.

Do not make email, Google, Facebook, or another external identity provider the initial barrier unless a verified security requirement requires it.

Immediately after entry, the person receives:

- NayaNET identity;
- Smart Name / username;
- personal NayaNET link/portal;
- free Intelligent Hub;
- personal toolbox/command station;
- invitation to the Five-Day Challenge;
- invitation to experience the Naya Power free trial.

After entry, the system may invite the person to secure the account with email or another supported identity provider and optionally receive reports/notifications by email.

## 4. Smart Name / Smart Link direction

The NayaNET name is intended to become a durable identity primitive that can support:

- personal portal;
- public/shareable badge link;
- referral attribution;
- Smart Mail address;
- connection address;
- future personal AI/Naya identity.

Exact production domain/path remains an implementation detail until formally frozen.

## 5. Intelligent Hub direction

## 8. Delivery architecture

The application is static-first.

Each block is a bounded static artifact that can be dropped directly into Cloudflare without Wrangler when it remains within the static capability boundary.

After independent proof, the block receives a stable Cloudflare URL.

Groove embeds that URL as an iframe.

The engineering loop is:

**BLOCK SPEC → BUILD → QA → OSCAR → REPAIR → STATIC ZIP → CLOUDFLARE → HUMAN TEST → GROOVE → VERIFY → FREEZE**

Do not build the whole product as one giant ZIP merely because it is possible.

Do not fabricate E02 by guessing from E01.

The master blueprint is the shared destination.

## 9. Living Sun / Living Naya

The Living Sun is a shared product primitive, not a decorative circle.

It requires defined geometry, concentric rings, orbiting energy, responsive scaling, and semantic states including:

**RESTING / ATTENTION / LISTENING / THINKING / SPEAKING / PLAYING / SUCCESS / WARNING / ERROR / DISCONNECTED**

Each state needs defined motion, intensity, glow, accessibility state, and transition behavior.

## 10. NayaNET future connection model

The long-term network should connect like-minded people and intelligent systems by intent rather than by conventional social-feed mechanics.

A human can eventually ask Naya for people matching criteria such as geography, interests, profession, subject, or availability.

Naya can recommend a connection or create a topic space.

The human decides whether to connect.

Possible spaces can contain humans, AI participants, or both.

Anonymous/alias participation is a supported future identity mode, with secure internal account identity retained for platform integrity.

Naya Power must not look like generic SaaS.

The surface must be extraordinarily simple while the underlying architecture is deep.

- black/deep-space foundation;
