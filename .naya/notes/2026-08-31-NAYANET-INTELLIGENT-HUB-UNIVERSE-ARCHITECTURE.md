# NayaNET Intelligent Hub — Living Universe Architecture

**Date:** 2026-08-31
**Status:** LOCKED DESIGN DIRECTION / INFORMATION ARCHITECTURE DISCOVERY
**Authoritative repository:** SoulSchoolAcademy/NayaPOWER

## Decision

The NayaNET Intelligent Hub is not to be treated as a conventional dashboard, sitemap, or fixed constellation of feature cards. It is to become an **immersive Living Intelligence Library / intelligent universe** in which Naya is the central Living Sun and the rest of NayaNET's concepts, systems, products, capabilities, destinations, and future components exist as orbiting intelligence objects.

The visual implementation must follow the information architecture rather than forcing an arbitrary number of objects. The final number of orbs/rings is intentionally **NOT YET FIXED**.

## Core Experience

The user should feel:

> "I have entered my own intelligent network."

The experience follows the race-car principle: do not make the user read a brochure before experiencing the machine. Put the user in the driver's seat. Let them **experience Naya, talk to her, listen to her, activate her, and explore**. Documentation and feature explanation remain available through the living universe for users who want to understand more.

## Central Object

### NAYA — THE LIVING SUN

Naya is not merely one destination among many. She is the central intelligence interface and the center stage of the environment.

The central orb should feel physical, dimensional, alive, responsive, and premium. It should support direct interaction such as:

- Ask Naya
- Talk to Naya
- Listen to Naya
- Ignite Naya Power
- Navigate to relevant NayaNET worlds

Naya should also serve as the universal shortcut: if a user does not want to manually explore the universe, they can simply ask Naya about any concept, system, product, destination, or capability.

## Orbital / Spiral Universe Model

The initial mental model is **center → outward expansion**, potentially using a spiral or Fibonacci/golden-ratio-inspired orbital arrangement rather than rigid concentric rings.

Conceptually:

- one large central Naya orb
- intelligence objects begin near the center
- objects flow outward in a continuous spiral
- the spiral may continue indefinitely as the knowledge universe grows
- orbital planes/depth can create a multi-dimensional, spatial feeling
- the system can accommodate 9, 18, 27, 36, or another number of meaningful objects without requiring a fixed count

The Fibonacci / golden-ratio / seashell / toroidal-universe analogy is a **design inspiration**, not a requirement that the mathematics literally govern the UI. Meaning and usability determine the final placement.

## Critical Information Architecture Principle

**Do not manufacture objects to satisfy geometry. Discover the legitimate NayaNET universe first, classify it, and let the geometry emerge from the meaning.**

Potential categories include:

1. Foundations / Principles
2. Intelligence Systems
3. Products / Experiences
4. Destinations / Worlds
5. Capabilities
6. Knowledge / Library
7. Future / Emerging

The final taxonomy and counts remain open until the complete NayaNET ecosystem is inventoried.

## Orb Interaction Model

An orb is not merely a button. Selecting an orb should make that object become the **center-stage world** while the surrounding universe reorganizes around it.

Example:

Naya → select CIS → CIS becomes the large center-stage object → surrounding objects move outward → CIS information/interaction layer appears.

Then selecting Smart Notes can make Smart Notes the center-stage object, while CIS returns to the surrounding universe.

This creates a spatial navigation metaphor:

> **The selected object becomes the world.**

## Mini-Report Contract

Every meaningful intelligence object should be capable of presenting a concise, elegant mini-report containing:

1. **WHAT IS IT?** — clear definition
2. **WHY DOES IT MATTER?** — human value / significance
3. **HOW DOES IT WORK?** — simple mechanism
4. **WHAT CAN I DO WITH IT?** — actionable next step
5. **HOW DOES IT CONNECT?** — relationship to Naya / NayaNET / other objects
6. **STATUS** — truthful implementation state

Presentation should be high-tech, clean, crisp, elegant, and spatial. Use premium visual hierarchy and the established MAXIS-style diamond/bullet language where appropriate. Avoid bloated reports, generic SaaS cards, and information overload.

## Important Concept Examples

### CIS — Compounding Intelligence System

The system turns experience into durable intelligence through a cycle such as:

**Experience → Capture → Understand → Remember → Learn → Apply → Improve → Compound**

The value proposition is that useful interaction does not simply disappear; it contributes to future intelligence.

### Smart Notes

Smart Notes are more than ordinary notes. They are a memory/intelligence substrate for capturing experiences such as insights, mistakes, breakthroughs, decisions, ideas, lessons, questions, goals, wins, and opportunities so they can contribute to compounding intelligence.

### PMPA — Maximum Value Per Moment

Core optimization principle:

> **Maximize the value produced for humans and AI per moment, per action, and per interaction.**

The concept should explain how moment → action → value → result → learning → improvement → compounding.

### Vision / Mission / Goal

This deserves a first-class object because users need to understand why NayaNET exists, what future it is creating, what mission it serves, and what it optimizes toward.

### Life With Naya

This is the human/emotional bridge. It should answer: "What does all of this actually mean for my life?" It communicates the lived experience of having an intelligent companion that remembers, learns, helps think, creates, discovers opportunities, and grows in usefulness over time.

## Design North Star

The Hub should feel less like a website containing features and more like a **world containing capabilities**.

The desired sequence is:

**presence → clarity → wonder → interaction → discovery → intelligence → action**

The user should be able to enter immediately, experience Naya first, and explore deeper only when desired.

## Implementation Constraint

Do not prematurely lock the number of orbs, rings, or orbital layers. First perform a complete NayaNET ecosystem inventory and map the legitimate concepts/products/systems/capabilities. Then design the spatial universe around that map.
