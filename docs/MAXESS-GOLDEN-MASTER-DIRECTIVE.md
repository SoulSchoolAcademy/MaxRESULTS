# 01 — GOLDEN MASTER RULE

V4 defines the product, visual system, psychology, ownership, and anti-drift rules.

This Golden Master defines the reference-result constraints that remove the remaining visual and execution ambiguity.

When V4 and this document conflict, this document governs only the specific reference-result details it explicitly defines. All other V4 rules remain active.

The implementing AI must NOT:

- invent a different visual metaphor because it prefers it;
- replace a locked object with a generic equivalent;
- flatten a primary object;
- introduce competing visual focal points;
- create copy merely to fill empty space;
- expand scope without evidence;
- rebuild unrelated sections during a local edit;
- claim visual quality from automated QA alone.

Golden Master principle:

**DESCRIBE IT → VISUALIZE IT → CONSTRAIN IT → BUILD IT → PROVE IT.**

INTERPRET
REASSURE
RECOGNIZE

PERSONALIZE
CONVERT.

Copy classes:

Must not change without explicit human approval.

DATA-FILLED:
Exact sentence structure with defined variables from authoritative data.

GENERATED-BY-NAYA:
Permitted only for interpretation inside the approved tone, length, structure, and claim boundaries.

Generated Naya interpretation must be:

- warm;
- direct;
- intelligent;
- useful;
- grounded;
- specific;
- never generic motivational filler;
- never hype-heavy;
- never manipulative;
- never diagnostic beyond the data;
- never presented as certainty when the data supports only a signal.

90 words unless the section contract explicitly permits more.

# 12 — OPTICAL QUALITY RULES

All compositions must be judged by perceived balance, not only numerical alignment.

The implementing AI must inspect:

- optical center;
- silhouette;
- negative space;
- edge density;
- contrast hierarchy;
- visual weight;
- glare concentration;
- text-to-object proportion;
- distance between primary and secondary objects.

A mathematically centered design can still fail.

If the composition looks visually tilted, crowded, weak, flat, or cheap, correct it before completion.

# 15 — EDIT BOUNDARY GOLDEN MASTER

Each component has one active owner.

Each edit must declare:

REQUEST
→ COMPONENT
→ OWNER
→ SOURCE REGION
→ OLD STATE
→ NEW STATE
→ EXPECTED DELTA
→ LOCAL TEST.

Micro edits must not rewrite unrelated source.

A micro edit is successful only when:

- source delta is non-zero;
- target component changed;
- unrelated regions remain unchanged;
- syntax is valid;
- local behavior remains valid;
- checkpoint is committed.
