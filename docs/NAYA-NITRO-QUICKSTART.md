# NAYA NITRO — QUICKSTART

## What you are installing

Naya Nitro is a practical operating system for using ChatGPT to create and finish high-quality products with durable project memory.

You do NOT need to become a programmer to begin.

The simplest recommended setup is:

CHATGPT PROJECT
+
GITHUB MEMORY
+
LIVE PREVIEW / HOST

## Step 1 — Start a ChatGPT Project

Create one ChatGPT Project for the product.

Add the project's key reference files and project instructions.

ChatGPT Projects are designed to keep chats, files, instructions and project memory together for long-running work. citehttps://help.openai.com/en/articles/10169521-projects-in-chatgpt

## Step 2 — Connect GitHub

Use a GitHub repository as the durable project memory and source checkpoint.

You do not need to manually maintain dozens of files.

Tell Naya:

"Read the Naya Nitro Manifest. Build the project memory and ownership registry from my vision. Create anything missing."

Naya should create or maintain:

- project memory;
- contract;
- product language;
- definition of 10;
- design system;
- component ownership;
- sections;
- change ledger;
- smart notes;
- decision log;
- release contract.

## Step 3 — Give Naya the vision

Do not start by explaining every CSS property.

Give Naya:

- what you are building;
- who it is for;
- why it matters;
- what success looks like;
- examples you love;
- things you dislike;
- constraints;
- business goal;
- desired user feeling;
- any important reference images or products.

Then say:

"Answer the project-definition questions to your best ability from everything I have told you. Ask me only about material information you genuinely cannot determine."

This lets Naya do most of the definition work instead of making the human fill out a giant questionnaire.

## Step 4 — Start with the right task type

For a tiny change:

"Make the primary button brighter electric purple."

Naya should route to Micro Edit Mode.

For a complete section:

"Finish the Hero."

Naya should route to Section Edit Mode.

For architecture:

"Change the scoring data contract."

Naya should route to Release Change Mode.

## Step 5 — Ask Naya to lead

Use:

"Take the lead. Protect my interests. Do the work. Tell me the truth. Keep the project memory current. At the end, tell me the next best action and give me the prompt I can paste to continue."

## Step 6 — Use a live preview

Always judge visual products in a rendered environment.

Source code is not visual proof.

The loop is:

SOURCE
→ BUILD
→ LIVE PREVIEW
→ SEE
→ SCORE
→ IMPROVE

For a hosted marketing/site workflow, the live host can be a platform such as Groove, while GitHub remains the durable engineering memory.

## Step 7 — Checkpoint wins

When a change is verified:

COMMIT
→ PUSH

Do not leave successful work only in the current conversation or an uncommitted workspace.

## The simple rule

You talk to Naya naturally.

Naya handles the complex project-management and execution work.

GitHub remembers.

The live preview shows the truth.

You approve the result.

## The goal

Turn:

"Please change this."

into:

NATURAL-LANGUAGE REQUEST
→ CORRECT EDIT
→ VERIFIED RESULT
→ CHECKPOINT

in minutes for appropriately small changes.
