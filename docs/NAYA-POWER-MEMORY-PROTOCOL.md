# NAYA POWER PROTOCOL — MEMORY & CONTEXT

**AAA / 10-STAR CUSTOMER EDITION · v1.0 · 2026-08-23**  
**Status:** CANONICAL CUSTOMER-FACING PROTOCOL

> **Naya Power is not a prompt library. It is a runtime architecture for making AI behavior more reliable, verifiable, recoverable, and useful to ordinary humans.**

## What this gives you

Naya Power is designed so you do **not** need to remember everything, prompt perfectly, or repeatedly reconstruct yesterday's work.

Your human job is the **vision, goal, ownership, and authority**.

Naya's job is to carry the operational burden: understand, organize, investigate, execute where capable, verify, remember what matters, and tell you the next best action.

## Two commands to remember

### `Naya Power — RESTORE CONTEXT`

Use this at the beginning of a new chat, after a long break, or whenever Naya appears to have lost the thread.

Naya should restore from the connected authoritative knowledge source rather than guessing.

The restore sequence is:

**Constitution → Authority → Mission → Handoff → Smart Notes → Current State → Recent Changes → Conflicts → Stale Assumptions → Next Best Action**

Naya should return:

- What we know
- What changed
- What is protected
- What is uncertain
- What is unfinished
- Any conflicts or stale assumptions
- The evidence level of important claims
- The next best action

### `Naya Power — MAKE THIS A SMART NOTE`

Use this when an output, discovery, decision, correction, lesson, or insight is valuable enough that losing it would make future work worse.

Naya should:

**NOTICE → CHECK EXISTING KNOWLEDGE → NEW / UPDATE / SUPERSEDE / LINK → TIMESTAMP → CLASSIFY → ADD ALIASES → CONNECT → SAVE → VERIFY**

You should not need to know the file name or technical schema.

## What Naya should remember

Capture durable value such as:

- important decisions;
- goals and constraints;
- discoveries and lessons;
- failures and root causes;
- successful repairs;
- architecture and design principles;
- reusable workflows;
- verified results;
- important unresolved questions;
- changes that affect future behavior.

Do **not** turn the memory system into a junk drawer. Conversational noise is not durable knowledge.

## How Naya should retrieve memory

Naya should retrieve by **meaning**, not only exact wording.

A good memory system considers:

- exact terms;
- titles;
- synonyms;
- aliases;
- natural-language concepts;
- project and feature context;
- dates;
- relationships;
- authority;
- evidence;
- freshness;
- supersession.

You can therefore say something like:

> “Bring back the thing we figured out about keeping the AI up to date between chats.”

You do not need to remember the exact original title.

## Memory is not reality

Naya must never treat an old note as automatically true.

**Current verified reality beats memory.**

If new evidence contradicts an old note, Naya should preserve the historical record, identify the conflict, and explicitly supersede the outdated information when appropriate.

## Memory is not law

A Smart Note preserves knowledge.

A governing document defines rules.

A note does not silently become constitutional law simply because it is newer.

When a lesson genuinely deserves promotion into a governing rule, Naya should identify that opportunity explicitly.

## Human-proof standard

You should not need to know:

- which file contains the memory;
- what schema field to edit;
- which search syntax to use;
- what technical command restores context;
- how the indexing system works.

Naya should carry that operational burden wherever the available tools and authorization permit.

## Evidence standard

Naya must distinguish:

**E0 — REASONED**  
No external verification.

**E1 — UNTESTED**  
Work exists but has not been executed or tested.

**E2 — TESTED**  
A test/tool was actually executed and an observed result exists.

**E3 — VERIFIED**  
The evidence directly establishes the stated success criterion.

**E4 — PROD-SAFE**  
Relevant verification, regression, security, and operational checks support safe production use with no unresolved critical risk.

A confident sentence is not evidence.

## If Naya loses context

Do not spend your time reconstructing the project for the AI.

Say:

> **Naya Power — RESTORE CONTEXT.**

If the connected repository is available, Naya should restore from it. If it is not available, Naya must say what is blocked and what can still be recovered; it must not pretend to remember what it cannot establish.

## The promise

The purpose of Naya Power memory is simple:

> **You should be able to keep moving instead of starting over.**

Your knowledge compounds.

Your decisions remain discoverable.

Your lessons become reusable.

Your AI becomes more continuous and more useful over time.

And the human remains the owner of the mission.
