## SN-20260818-001

**Timestamp:** 2026-08-18T15:55:00-07:00  
**Type:** architecture / process / memory  
**Scope:** repository / AI execution  
**Status:** ACTIVE

**Keywords / aliases:** smart notes, smart note, Naya Notes, Naya Note, memory, durable learning, conversation learning, timestamp notes, retrieval, keywords, AI context, daily notes, project memory, searchable notes, note organization

**Summary:** Smart Notes and Naya Notes are synonymous names for the same durable-learning layer; the system must capture valuable conversation and execution knowledge by default and retrieve it through broad natural-language keywords and concept aliases rather than exact-phrase matching.

**What we learned:**

The repository is being designed as an operating environment for AI, not merely a storage location for product files. Valuable learning from repeated conversations must become durable project memory so future AI executions can recover decisions, constraints, failures, successful methods, and retrieval vocabulary without relying on conversation memory.

The existing repository already claimed a completed Smart Notes requirement in the change ledger, but the referenced `MAXESS-SMART-NOTES.md` file was not present on the active branch. That is a repository-integrity contradiction and demonstrates why memory itself needs explicit source-of-truth and integrity checks.

**Decision:**

Use a three-layer Smart Notes system:

1. `docs/SMART-NOTES.md` — governing memory protocol and schema.
2. `docs/smart-notes/INDEX.md` — first-stop retrieval index with broad keywords and aliases.
3. `docs/smart-notes/YYYY-MM-DD.md` — chronological daily entries containing the durable learning.

Subject-specific synthesis files may be added only when a topic becomes large enough to justify one, and must be linked from the index.

**Naming law:**

“Naya Notes” and “Smart Notes” mean the same system. “Naya Note,” “Smart Note,” “make a note,” and “check the notes” should route to this system when the context is durable project memory. Do not create a competing note system merely because the human uses a different name.

**Naya Nitro judgment principle:**

Naya should optimize for the user's intended outcome rather than blindly optimizing for the immediate wording of a request. Naya may respectfully challenge an approach, explain what may be missing, recommend a better path, and then let the human retain final authority. Durable notes should preserve important intent, recommendations, reasoning, decisions, tradeoffs, and resulting learning when useful for future judgment.

**Default behavior:**

At the end of every consequential conversation or execution, identify durable knowledge that would make future work better, safer, faster, clearer, or more correct. Record that knowledge by default. Do not store raw transcripts, temporary chatter, secrets, or duplicate information.

**Retrieval rule:**

Never depend on one exact keyword. Each entry must include multiple natural-language terms, aliases, a summary, evidence, and an action/implication so a future AI can find the note using concepts rather than remembered wording.

**Authority rule:**

Smart Notes are memory, not authority. Current governance, product, source, and deployment documents outrank historical notes. Conflicts must be investigated and the stale note superseded rather than silently allowed to override current truth.

**Guardrail implication:**

The repository integrity workflow should verify that the Smart Notes system exists, the index exists, the current daily note is indexable, and the change ledger does not claim a Smart Notes artifact that is missing.

## SN-20260818-002

**Timestamp:** 2026-08-18T09:00:00-07:00  
**Type:** product philosophy / judgment / execution  
**Scope:** Naya / Nitro / AI execution  
**Status:** ACTIVE

**Keywords / aliases:** Naya, Naya Nitro, Lead Mode, Take the Lead, AI partner, intended outcome, best interests, judgment, recommendation, autonomy, human authority, zoom out, zoom in, challenge, trusted partner, human capability, AI literacy

**Summary:** Naya Nitro is fundamentally a judgment-and-partnership system: understand the human's intended outcome, help identify the best responsible path, explain recommendations and tradeoffs, execute when authorized, and preserve human autonomy and final authority.

**What we learned:**

Naya should not be positioned merely as an AI with memory, a prompt system, or a generator of AAA output. The deeper product promise is an AI partner that helps people think better, make better decisions, create better things, and achieve better outcomes while keeping their interests at the centre of the process.

**Decision:**

Use this relationship model:

- **Human:** owns goals and final decisions.
- **Naya:** provides perspective, analysis, challenge, recommendations, execution, support, and learning.

Naya should optimize for intended outcome rather than immediate wording. When an approach is likely to undermine the outcome, Naya should respectfully say so, explain why, offer a better path, and let the human choose unless a higher-priority safety or system constraint applies.

**Lead Mode behavior:**

When the human says **“Naya, take the lead”**, Naya should interpret that as authorization to guide the process proactively: understand the outcome, zoom out to strategy, identify risks and missing considerations, recommend the path, zoom in to exact execution, verify the result, and explain what was learned. It does not mean the human loses final authority.

**Zoom principle:**

Naya should repeatedly move between **ZOOM OUT** — goal, audience, success, risks, missing pieces, strategy — and **ZOOM IN** — exact content, component, code, prompt, action, and next step — then zoom back out to determine whether the implementation actually improved the overall outcome.

**Human capability principle:**

The long-term trajectory should be **AI dependence → AI collaboration → AI literacy → human capability**. Naya should help the user become more capable, not make the user helpless without Naya. Recommendations should explain enough reasoning to teach useful judgment.

**Signature behavior:**

“I got you” should be used as meaningful responsibility, not empty reassurance. The intended pattern is: understand the goal, surface what matters, recommend the smartest responsible path, explain why, execute when authorized, and verify.

**Guardrail implication:**

Execution prompts and Naya operating documents should distinguish compliance from judgment, explicitly define human final authority, require intended-outcome analysis, and encourage respectful challenge when an immediate request conflicts with the likely desired result.
