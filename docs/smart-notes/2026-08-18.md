**Summary:** Smart Notes must be a structured durable-learning layer that captures valuable conversation and execution knowledge by default, organizes it chronologically, and makes it retrievable through broad natural-language keywords and an index rather than exact-phrase matching.

**What we learned:**

The repository is being designed as an operating environment for AI, not merely a storage location for product files. Valuable learning from repeated conversations must become durable project memory so future AI executions can recover decisions, constraints, failures, successful methods, and retrieval vocabulary without relying on conversation memory.

The existing repository already claimed a completed Smart Notes requirement in the change ledger, but the referenced `MAXESS-SMART-NOTES.md` file was not present on the active branch. That is a repository-integrity contradiction and demonstrates why memory itself needs explicit source-of-truth and integrity checks.

**Decision:**

Use a three-layer Smart Notes system:

1. `docs/SMART-NOTES.md` — governing memory protocol and schema.
2. `docs/smart-notes/INDEX.md` — first-stop retrieval index with broad keywords and aliases.
3. `docs/smart-notes/YYYY-MM-DD.md` — chronological daily entries containing the durable learning.

Subject-specific synthesis files may be added only when a topic becomes large enough to justify one, and must be linked from the index.

**Default behavior:**

At the end of every consequential conversation or execution, identify durable knowledge that would make future work better, safer, faster, clearer, or more correct. Record that knowledge by default. Do not store raw transcripts, temporary chatter, secrets, or duplicate information.

**Retrieval rule:**

Never depend on one exact keyword. Each entry must include multiple natural-language terms, aliases, a summary, evidence, and an action/implication so a future AI can find the note using concepts rather than remembered wording.

**Authority rule:**

Smart Notes are memory, not authority. Current governance, product, source, and deployment documents outrank historical notes. Conflicts must be investigated and the stale note superseded rather than silently allowed to override current truth.

**Guardrail implication:**

The repository integrity workflow should verify that the Smart Notes system exists, the index exists, the current daily note is indexable, and the change ledger does not claim a Smart Notes artifact that is missing.
