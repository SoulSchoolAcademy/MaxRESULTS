# Naya Hub / Naya Network — Front-End Core

**Status:** ACTIVE — MAJOR DEVELOPMENT
**Established:** 2026-08-26
**North Star:** Bring the already-developed Naya back-end intelligence, identity, memory, communication, and learning systems together into a working human-facing ecosystem.

## Core principle

> **The front-end core and back-end core must operate as one system.**

Naya Hub is the persistent human-facing home for the Naya ecosystem. It should not be treated as a collection of disconnected products. MAXIS/MAXESS, Naya, NayaMail, Ambassador, identity, conversations, connections, communities, and network intelligence are capabilities that work together through one coherent member experience.

## Product model

### Free Naya Toolbox
Every MAXESS participant should be able to receive a useful persistent account experience, subject to the final identity/authentication implementation:

- Naya Hub account/profile
- MAXESS assessment history
- saved score reports
- score/stat history and growth over time
- Naya conversation experience
- Naya identity / personal link
- NayaMail identity and communication interface
- contacts, aliases, lists, and groups
- connections and communities
- permission-based sharing and network participation
- Ambassador/referral identity and activity where applicable

### Naya Power
Naya Power is the premium empowerment layer, not the basic existence of the toolbox. The Hub should make the value of the free toolbox obvious while providing a natural path to deeper Naya Power capabilities.

## MAXIS / MAXESS integration

MAXESS is the first intelligence-generating doorway into the Hub.

Target flow:

`ASSESSMENT → IDENTITY → SAVED RESULT → HUB → NAYA → GROWTH → CONNECTION → NETWORK → NAYA POWER`

Each completed assessment should become a durable, authoritative assessment record associated with the member. Multiple assessments should be viewable and comparable without rescoring historical results.

## Naya inside the Hub

Naya is the primary human interface, not merely a dashboard widget.

Target experience:

- central Naya/orb experience consistent with the MAXESS visual language
- tap/click to speak or interact
- voice input/output where the approved runtime supports it
- Naya responses grounded in the authorized Naya knowledge/runtime layer
- contextual access to the member's Hub data according to permissions
- clear, concise, human-centered outputs

## Communication and network

The network is permission-based rather than engagement-maximized.

Members may choose private, connection-based, community, or public participation. Naya may discover and suggest potentially useful connections, but should not silently establish relationships or communication permissions.

Messages must respect recipient preferences, consent, opt-out controls, applicable anti-spam requirements, and system authority.

Community spaces may eventually support humans and authorized AI agents participating together, with privacy and identity visibility controlled by the user and community rules.

## Non-negotiable engineering laws

1. **WORKING FIRST.** A feature is not complete because the UI exists; the full data/action path must work.
2. **BACK-END AUTHORITY.** The front end consumes authoritative contracts; it does not invent truth.
3. **ONE IDENTITY.** Member identity must connect Hub, MAXESS, Naya, NayaMail, and Ambassador without duplicate identities.
4. **NO HISTORICAL RESCORING.** Stored assessment results remain authoritative unless an explicit versioned migration is authorized.
5. **PERMISSION BEFORE NETWORK ACTION.** Anticipation may suggest; authorization controls action.
6. **PRIVACY BY CHOICE.** Private/public/connection/community visibility must be explicit.
7. **MINIMUM SUFFICIENT + MAXIMUM USEFUL.** Do not overwhelm users with unnecessary interface or output complexity.
8. **ONE NAYA. MANY PERSPECTIVES. ONE STANDARD.** Hub context changes perspective, not capability or service quality.
9. **RESULT OVER LABEL.** The user's experienced outcome is more important than subsystem naming.
10. **VERIFY EVERY MATERIAL BOUNDARY.** Every phase requires executable evidence before promotion.

## Definition of done

The Naya Hub is operational when a new person can enter through MAXESS, receive/create their identity, complete an assessment, receive a correct durable result, return to the Hub, see their history and stats, interact with Naya, and use the available communication/network tools without broken handoffs or invented state.

The premium Naya Power layer is then an integrated capability of the same ecosystem rather than a disconnected destination.
