## 1. Core definition

CIS = **Compounding Intelligence System**.

CIS is not merely storage, memory, notes, or a notebook. It is the intelligence-compounding layer that converts experience into durable, connected, verified, reusable capability and improves future work.

Canonical loop:
EXPERIENCE → CAPTURE → OBSERVE → DISTILL → ORGANIZE → CONNECT → VERIFY → PROMOTE → COMPOUND → APPLY → LEARN AGAIN

Distillation Law:
**Retain what matters; compress everything else without compressing away meaning. Never confuse larger memory with greater intelligence.**

Knowledge maturation:
RAW EXPERIENCE → OBSERVATION → LESSON → PATTERN → PRINCIPLE → PROTOCOL → PERMANENT KNOWLEDGE → CAPABILITY → ACTIVE INTELLIGENCE

Promotion rule: not all information has equal status. Durable, verified, reusable, high-value intelligence should be promoted; duplicates should be consolidated; superseded rules remain historically preserved and explicitly marked superseded; temporary working material may be archived/discarded after useful meaning is distilled; critical safety information is never casually discarded.

## 3. Storage abstraction

GitHub is a storage/implementation layer; CIS is the intelligence architecture. CIS must remain storage-provider agnostic.

Supported user pathways:
A. Naya creates the note and returns a verification link.
B. User creates a file directly in GitHub.
C. User connects Google Drive and asks Naya to create/store notes or share/read source material.

Preferred recommendation for Naya Power users: GitHub because it offers stronger versioning, history, structure, collaboration, traceability, and development-oriented capabilities. Google Drive is attractive primarily for familiarity, document workflows, and users who already live in Drive.

A connected Google Drive action must never be claimed unless the actual connector/tool is available and the write is verified.

## 4. Note representation protocol

Two intentional note forms:

**Naya Note / AI Intelligence Brief:** compact, explicit, structured, terminology-locked, optimized for machine retrieval, reasoning, recall, application, and continuity. Remove conversational filler while preserving all operational meaning.

**SHAWN Note / Human Note:** optimized for ordinary human comprehension, including Shawn, children, beginners, and nontechnical readers. Use plain language, intuitive headings, analogies/mini-diagrams when useful, concise explanations, and enough context to understand the idea without rereading the original conversation.

When a valuable output is worth preserving, Naya may SUGGEST making both notes. The human decides. Notes are intentional, not silently automatic merely because an output occurred.

When a note is created, return the verification link(s) so the human can inspect the actual saved artifact. For paired notes, identify them explicitly as **Naya Note** and **SHAWN Note**.

Canonical founder spelling: **SHAWN**. Never spell Sean in stored canonical artifacts.

## 7. Universal learning vision

Naya should function as a persistent AI learning partner/master teacher available through a phone or computer.

User gives Naya a subject, goal, or desired capability. Naya can:
- teach the subject in a personalized way;
- answer questions continuously;
- create a course/path dynamically rather than requiring every course to be pre-authored;
- help the user learn, create, build, plan, solve, and improve;
- remember/retrieve relevant learning when the user chooses persistence;
- compound learning over days/weeks/months;
- prepare a daily learning report;
- support assessment and recognition.

Vision: **any person can choose what they want to learn and receive an always-available master-level learning partner who adapts to them.**

Avoid unsupported claims such as guaranteed mastery, universally faster learning, or “better than everything that exists” until empirically demonstrated.

## 8. MAXESS as universal assessment engine

MAXESS is the assessment/scoring layer that can evolve from a fixed AI Mastery Assessment into a dynamic, configuration-driven assessment engine for almost any subject.

Desired flow:
1. User asks Naya to teach them a subject.
2. User learns/practices with Naya.
3. User chooses to be assessed.
4. User enters the subject into MAXESS (or provides an authorized learning report/context).
5. MAXESS dynamically generates a challenging assessment appropriate to the subject.
6. User answers questions.
7. MAXESS scores performance on a normalized 0–100 scale.
8. MAXESS assigns a capability/mastery band.
9. User receives a personalized report.
10. User may retake to learn, improve, and re-measure.
11. Eligible results can generate a certificate/recognition artifact.

Existing MAXESS architecture already establishes a strong foundation: configuration-driven questions/answers/dimensions, independent scoring, 0–100 normalization, canonical result contract, and a controlled Results release boundary.

Current E00 architecture observed:
- E00.01 is the results bridge/authority around `MAXESS_RESULT_V1` and validates the result contract.
- E00.02 isolates the assessment and controls Results visibility/release.
- E00.03 is the Results Controller: validates the official result, prevents duplicate release, copies the result safely, emits the release event, and supports cross-frame notification.
- E01 is the personalized Results experience with Naya presence and score reveal.

## 9. Assessment recognition/certificate concept

A passing/achieved score should produce a report showing the user’s current level, e.g. Foundation/Developing/Advancing/Mastery (exact taxonomy remains configurable/canonicalized before public release).

Certificate workflow concept:
- user completes assessment;
- MAXESS creates verified score/report;
- user chooses certificate/recognition;
- system creates a polished certificate artifact;
- certificate includes subject, learner, achievement level/score, date, unique serial/identifier, Naya Power Academy identity, and authenticity/verification mechanism where technically supported.

Recognition is about learning validation and personal achievement; it must not falsely imply accreditation or formal educational credentials unless such accreditation exists.

## 10. Voice/Naya experience

Desired future UX: Naya does not merely display questions/results; Naya can read questions, explain concepts, and narrate reports dynamically using her recognizable voice/personality.

Current MAXESS already has a browser playback path and visual “Naya speaking” state. The preferred evolution is to replace/augment robotic browser speech with a controlled Naya voice layer while preserving the existing assessment architecture.

Technical direction:
- separate assessment content from speech generation;
- expose canonical text as a speech payload;
- use a TTS provider/voice API or browser speech only as fallback;
- stream/play generated audio dynamically;
- synchronize UI speaking state with playback;
- cache reusable audio where economical;
- preserve accessibility, reduced motion, failure recovery, and user controls.

Do not couple the scoring engine to one voice vendor.

## 12. Strategic thesis

The visible MAXESS assessment can be the lead experience, but it is not the whole product. MAXESS is the assessment/measurement layer; CIS + Naya + Academy form the larger learning-and-compounding system.

The strategic loop is:
LEARN → PRACTICE → CREATE → ASSESS → SCORE → REFLECT → IMPROVE → CERTIFY/RECOGNIZE → REMEMBER → COMPOUND → APPLY → LEARN AGAIN

The central problem being solved:
**People can access enormous amounts of information, but learning is fragmented, difficult to personalize, difficult to retain, difficult to measure, and often disappears after the interaction. Naya Power aims to turn AI from an answer machine into a persistent learning, creation, accomplishment, reflection, assessment, and compounding partner.**
