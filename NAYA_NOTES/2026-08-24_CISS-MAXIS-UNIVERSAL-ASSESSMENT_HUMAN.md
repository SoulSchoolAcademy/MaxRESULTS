**Date:** August 24, 2026
**Shawn + Naya**

## The simple idea
Imagine having a master teacher beside you whenever you want to learn something.

You pick the subject.
You ask Naya to teach you.
You learn at your own pace.
You can ask questions whenever you want.
You can practice and create things with what you learn.
Then you take a test to see what you actually know.

You get a score.
You see where you are.
You learn what you still need to work on.
You can take the test again.
You keep improving.

And over time, Naya can remember what you learned so you don't have to start from zero every time.

That is the bigger picture behind **Naya Power + MAXIS + CISS**.

MAXIS does not have to be an assessment about one subject.

**The same scoring engine can potentially score almost anything.**

So instead of building 1,000 different courses and 1,000 different tests, we build one smart assessment system that can create a new assessment around whatever subject the person chooses.

For example:

| You want to learn… | You could ask Naya to help you learn it | Then MAXIS could assess you |
|---|---|---|
| Spanish | Yes | Yes |
| Algebra | Yes | Yes |
| Programming | Yes | Yes |
| History | Yes | Yes |
| Biology | Yes | Yes |
| Photography | Yes | Yes |
| Business | Yes | Yes |
| AI | Yes | Yes |
| Anything else | That's the idea | That's the idea |

The point is not that every subject becomes magically easy.

The point is that **the learning partner, the assessment system, and the memory of the journey can stay with the person.**

**CHOOSE → LEARN → PRACTICE → CREATE → TEST → SCORE → DISCOVER GAPS → IMPROVE → TEST AGAIN → REMEMBER → GROW**

**OR**

## The technology idea
We should NOT build a separate app for every subject.

Instead, we build one assessment engine.

Think of MAXIS like a machine:

**SUBJECT IN → SMART TEST OUT → SCORE → REPORT**

The subject changes.
The machine stays the same.

That is the key architectural idea.

The system should create the questions and answer choices dynamically, but the scoring engine should remain deterministic and consistent.

---

## Next move
The smartest next step is not to rebuild everything.

It is to take the existing MAXIS code and make the assessment engine topic-agnostic:

1. Find exactly why the current scoring is failing.
2. Lock the canonical question/answer/scoring structure.
3. Add a subject/topic input.
4. Generate an assessment from that subject.
5. Feed the generated assessment into the existing MAXIS experience.
6. Make scoring deterministic and reliable.
7. Generate the report dynamically.
8. Add certificates and verification.
9. Then connect the experience back to Naya Power for the learning/improvement loop.

**Preserve what already works. Build the universal engine underneath it.**
