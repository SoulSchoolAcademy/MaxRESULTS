# MAXESS Results Integration Contract

## Authoritative flow

`E00` → `MAXESS_RESULT_V1` → `results.nayanet.app` → Results consumer → `window.MAXESS_RESULT` → E01–E04 dynamic hydration → existing E05–E09 static Results experience

E00 owns assessment questions, scoring, result-contract production, and the final handoff of the validated contract to the official Results host. The Results page owns Results sequencing and rendering. E00 must not inject Results HTML or render E01–E09 itself.

## North Star

When the user answers Question 15 and clicks **Continue once**:

1. the final response is committed;
2. the 15-response result is calculated and validated;
3. `MAXESS_RESULT_V1` is created;
4. the result is handed to `results.nayanet.app/#maxess-result=<payload>`;
5. the Results consumer decodes and validates the payload;
6. `window.MAXESS_RESULT` becomes the single runtime authority;
7. E01–E04 hydrate from that object;
8. existing E05–E09 remain present;
9. the complete Results page is visible.

No second click, no return to Question 15, no white-page dead end, no infinite spinner, and no visible E00/E00.xyz artifact underneath the Results experience.

## Live deployment responsibility

Groove deployment is manual. This repository stores the source and integration contract. The Results consumer must be installed in the published Results page at `results.nayanet.app`.

**Critical deployment rule:** GitHub source presence does not prove live Groove installation. The handoff is not considered LIVE VERIFIED until the published Results page receives a real assessment payload and the browser shows the complete Results experience with the real score.

## Consumer

`MAXESS-RESULT-CONSUMER-V2.html` remains the approved consumer for the standalone Results integration.

The consumer:

- reads `#maxess-result=` from the current URL hash;
- decodes URL-safe Base64 JSON;
- validates the `MAXESS_RESULT_V1` contract;
- publishes the authoritative object as `window.MAXESS_RESULT`;
- persists the valid result in session/local storage where supported;
- dispatches `MAXESS_RESULT_READY` and `maxess:result-updated`;
- tolerates late-loaded Results sections through bounded hydration;
- rehydrates on `hashchange` and `pageshow`;
- hydrates E01 and E02 from the same authoritative result;
- preserves the existing Results section renderers.

No demo score or fallback result is generated by the consumer.
