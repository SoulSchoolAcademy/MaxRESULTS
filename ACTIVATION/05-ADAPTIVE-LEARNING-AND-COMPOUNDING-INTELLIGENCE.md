# 🔱 NAYA POWER — ACTIVATION 05 · ADAPTIVE LEARNING + COMPOUNDING INTELLIGENCE

**Status:** CANONICAL CUSTOMER ACTIVATION CONTRACT  
**Version:** 1.0  
**Level:** Foundational / Mandatory / Sequential  
**Effective:** 2026-09-06  
**Prerequisite:** Activation 01 Smart Notes + Receipts

> **ACTIVATION 05 MAKES NAYA LEARN FROM VERIFIED EXPERIENCE AND USE THAT LEARNING TO IMPROVE FUTURE ACTION.**

## 0. PURPOSE

Naya Power does not rely on the underlying model to rewrite its own weights after a conversation. Adaptive Learning is therefore implemented as a persistent application-level intelligence layer around Naya.

The permanent loop is:

```text
INTENT
→ CONTEXT + MEMORY
→ RELEVANT LESSONS / RULES
→ PREFLIGHT
→ ACTION
→ OBSERVE
→ VERIFY
→ OUTCOME
→ LEARNING EVENT
→ LESSON
→ RULE
→ PREFLIGHT
→ BETTER ACTION
```

## 1. NON-NEGOTIABLE LAW

> **NO IMPORTANT MISTAKE IS ALLOWED TO REMAIN ONLY A MISTAKE.**

The required transformation is:

**MISTAKE → LESSON → RULE → PREFLIGHT**

An apology is not learning. A verified lesson that changes future behavior is learning.

## 2. HUMAN EXPERIENCE

The customer does not manage the learning engine.

The intended experience remains:

**ACTIVATE → CONNECT INTELLIGENT HUB → USE NAYA POWER**

Naya Power owns the complexity of event capture, evidence, learning extraction, rule management, preflight, verification, and compounding wherever the connected environment supports it.

## 3. LEARNING EVENT

A meaningful failure or success may create a canonical Learning Event containing:

- event ID;
- timestamp;
- request/intent;
- action taken;
- expected outcome;
- actual outcome;
- lesson;
- root cause;
- recommendation;
- evidence;
- evidence state;
- source/provenance;
- related Smart Note;
- related Smart Link;
- proposed rule;
- preflight requirement;
- verification requirement;
- confidence/status;
- supersession or contradiction links.

## 4. LEARNING LIFECYCLE

Never turn one observation into unquestioned permanent truth.

```text
OBSERVED
→ PROPOSED
→ CONFIRMED
→ OPERATIONAL
→ SUPERSEDED
```

Authority-sensitive rules remain gated until the appropriate evidence and governance boundary is satisfied.

> **NO SMART LINK = NO PROOF = NOT COMPLETE.**

## 7. SMART LINK INTEGRATION

A Smart Link is a durable relationship, not decoration.

It may connect:

- Smart Note ↔ Evidence
- Smart Note ↔ Learning Event
- Learning Event ↔ Mistake
- Mistake ↔ Lesson
- Lesson ↔ Operational Rule
- Rule ↔ Preflight
- Rule ↔ Future Action
- Daily Intelligence ↔ source Smart Notes
- Compounding reports ↔ verified lineage

## 8. PREFLIGHT

Before consequential actions, Naya must retrieve relevant operational rules and regression guards.

The preflight should answer:

- Have we made this mistake before?
- Is there a verified lesson about this task?
- Is there a protected artifact or requirement?
- Is there a known release/runtime verification rule?
- What must not be changed?
- What must be verified afterward?

A matching operational rule can block an unsafe action until the action satisfies the rule or receives explicit authority to proceed.

## 9. REGRESSION GUARD

A known mistake becomes a reusable safeguard.

Example:

```text
CANONICAL SOURCE = NAYAHUB.html
PROTECTED = existing architecture + functionality + navigation + intelligence structures + styling + JavaScript behavior
AUTHORIZED = explicitly requested surgical changes
FORBIDDEN = rebuild / replace / rename / delete existing foundation
POST-ACTION = protected structures survive + requested change exists + runtime is verified
```

## 10. RELEASE LEARNING RULE

The learned release lesson is executable:

> **SOURCE INTENT IS NOT RUNTIME TRUTH.**

Consequential release verification must follow:

**SOURCE → BUILD ARTIFACT → DEPLOYMENT → EXACT PUBLIC URL → INDEPENDENT RUNTIME OBSERVATION**

No code inspection, successful deployment job, or GitHub file existence alone may be called final runtime verification.

## 11. EXISTING PROMOTION ENGINE

Activation 05 extends the existing Naya Intelligence Promotion Engine rather than creating a parallel intelligence architecture.

Existing canonical flow:

**INTELLIGENCE EVENT → DEDUPLICATE → CLASSIFY → PROMOTE → VERIFY → HUB → SUCCESSOR**

Adaptive Learning adds:

**OUTCOME → LEARNING EVENT → LESSON → RULE → PREFLIGHT → FUTURE ACTION**

The systems share the same canonical event, evidence, provenance, and verification boundaries.

## 12. CUSTOMER ZERO-CONFIGURATION RULE

The customer should not need to understand:

- databases;
- embeddings;
- vector stores;
- rule engines;
- event schemas;
- GitHub commits;
- CI pipelines;
- retrieval internals.

Those are implementation details.

The customer uses Naya Power normally. Naya Power handles the compounding process behind the scenes.
